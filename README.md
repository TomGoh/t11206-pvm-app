# t11206-pvm-app

x-kernel 虚拟机的控制应用：一个页面，按需启动或停止 x-kernel 受保护虚拟机，并显示真实状态。

- 应用不持有虚拟机，只通过 `t11206-pvm-service` 的 `IXKernelVmControl` 接口发请求；离开页面、划掉或杀掉应用都不会停止虚拟机，重新打开显示同一实例。
- 打开应用和查询状态从不启动虚拟机。页面可见时订阅状态回调，离开时取消，不轮询；唯一的定时器是本地的运行时长显示。
- 显示：状态、原因、保护模式（明确标出“无客户机固件，镜像未经固件认证”）、启动方式（经 AVF，或控制服务直接运行 crosvm）、身份链（本阶段为“未启用”）、配置内存（注明是配置值）、虚拟处理器数、运行时长、上一实例资源是否已确认回收、上次结束原因。
- 按钮：已停止或失败时可“启动”；启动中、运行中可“停止”；回收待核实时按钮变为“重新核实回收”。请求发出后按钮保持禁用，直到收到结果或新状态。

## 控制台（下半屏）

- 下半屏是 x-kernel 的串口控制台，可以直接和客户机里的 shell 交互。串口由控制服务持有；打开应用时先显示服务保留的最近 64 KiB 输出，之后的输出实时推送。输出按“实例号 + 字节偏移”去重，发现缺口就重新挂接。
- 输入行回车（或“发送”）把这一行加换行发给客户机，回显由客户机负责。快捷键：Ctrl-C、Tab（先发出已输入的部分，用于补全）、上下箭头（历史命令）、Ctrl-D；“清屏”只清本地视图。
- 输入框要求 ASCII 键盘、不做组字（`textVisiblePassword` 与 `flagForceAscii`），否则拼音输入法会把命令变成汉字候选。
- 只有虚拟机运行时才能输入；实例结束后保留它的输出，直到下一次启动开始新的控制台。
- 终端模型 `TerminalBuffer` 处理 UTF-8、回车退格、颜色与粗体斜体、行内擦除、行编辑器用到的光标移动、清屏，并回答光标位置查询（客户机的行编辑器每次显示提示符都会问）。它是滚动缓冲（最多 1000 行），不是固定大小的屏幕，所以全屏程序不会像在真实终端上那样显示。
- 弹出软键盘时，控制台占到三分之二高度。

## 权限与签名

应用用平台证书签名（`certificate: "platform"`），以使用 `ServiceManager` 取得服务，并定义、持有签名权限 `com.kylinos.xkernelvm.permission.CONTROL_VM`；控制服务对 root 和 system 以外的调用方核验该权限。

## 构建

与 `t11206-pvm-service` 一起放进设备对应的 Android 源码树：`m XKernelVmControl`（依赖服务仓库的 `com.kylinos.xkernelvm-java`）。

## 测试

`host-tests/run.sh` 在开发机上测试终端模型 `TerminalBuffer`（需要 JDK 17 或更新版本）：输入取自客户机真实的控制台输出，`host-tests/stubs/` 里是它用到的几个安卓类的桩。GitHub 在每次推送和拉取请求时运行它（`.github/workflows/host-tests.yml`）；应用本身只能在 Android 源码树里编译，不在 CI 中构建。
